# Electron 桌面端开发交接记录

> 更新时间：2026-05-20  
> 当前阶段：macOS 本机开发验证已能启动；Windows 最终安装包后续到 Windows 环境打包  
> 目标：把现有 React 检测系统包装为桌面端离线客户端，复用 APK 端的“前端静态包 + 本地 Node/LowDB 服务 + ONNX Runtime Web 推理”思路，但按 Electron 桌面架构收口。

---

## 1. 当前结论

本轮已经创建 `electron-app/` 桌面端工程，并把 APK 端离线客户端的核心思路迁移到了 Electron：

- Electron 主进程启动 `BrowserWindow`，加载 `electron-app/www/index.html`。
- Electron 主进程异步 `require()` 内置 Express 服务，监听 `127.0.0.1/0.0.0.0:5001`。
- 前端在 Electron/移动端离线模式下默认请求 `http://127.0.0.1:5001/api`。
- LowDB 在 Electron 中改用 `app.getPath('userData')/db/db.json`，避免写入打包目录。
- ONNX 模型路径增加 `file://`/相对路径兼容处理，避免 Electron 下从硬盘根目录解析模型。
- Windows 打包配置已写进 `electron-app/package.json`，但最终 Windows 安装包建议在 Windows 机器打。

本轮已修复 Electron 启动卡在“加载中”的问题。根因是 `www/index.html` 原先仍是移动端构建产物，里面设置了 `window.__IS_MOBILE_APP__ = true` 并加载 APK 的 `node-launcher.js`。现在 `copy-assets.js` 会在同步资源时生成 Electron 专用入口和 `electron-launcher.js`，由 renderer 轮询内置桌面 API `/health` 后隐藏 loading。

2026-05-20 已完成 Electron 逐页审计：19 个主要页面均可在 macOS Electron 中渲染，`loading=false`，未再出现白屏、React 崩溃、`Unexpected token '<'`、`node-launcher` 卡住或 `/models/*.onnx` 解析到硬盘根目录的问题。`webSecurity: false` 已移除，CSP 已由 `copy-assets.js` 注入，最后一轮审计没有 Electron security error。

## 2. Electron 与 APK 的架构差异

### APK 端

APK 端路径：`android-app/`

- 壳：Capacitor WebView。
- 本地服务：`nodejs-mobile` 插件启动 Node。
- 启动器：`android-app/www/node-launcher.js` 等待 `cordova/deviceready`，调用 `window.nodejs.start('main.js')`。
- 前端标识：`window.__IS_MOBILE_APP__ = true`。
- 数据目录：Android 应用私有目录。

### Electron 桌面端

Electron 端路径：`electron-app/`

- 壳：Electron `BrowserWindow`。
- 本地服务：Electron 主进程直接 `require('src/server/main.js')` 启动 Express。
- 启动器：已改为 `electron-launcher.js` 轮询 `http://127.0.0.1:5001/health`，不再依赖 `cordova`、`nodejs-mobile` 或 APK 的 `node-launcher.js`。
- 前端标识：应该使用 `preload.js` 暴露的 `window.__IS_ELECTRON__ = true`。
- 数据目录：`app.getPath('userData')/db/db.json`。

结论：Electron 可以复用 APK 的离线 API、ONNX 推理和静态资源复制流程，但启动协调、环境标识、窗口生命周期、数据目录、打包方式要单独处理。

## 3. 本轮新增/修改文件

### 新增 Electron 工程

```text
electron-app/
├── package.json                 # Electron 依赖、启动、Windows 打包配置
├── package-lock.json
├── main.js                      # Electron 主进程，创建窗口并启动内置 Express
├── preload.js                   # 暴露 __IS_ELECTRON__ 与环境信息
├── icon.ico                     # Windows 图标
├── scripts/copy-assets.js       # 从主项目同步前端构建产物、WASM、ONNX、Node API
├── src/server/main.js           # 内置 Express 启动入口
└── www/                         # 当前同步出来的前端静态产物
```

注意：`electron-app/node_modules/` 和 `electron-app/www/models/` 被 `.gitignore` 忽略，不应提交。

### 主项目代码改动

- `src/lib/config.ts`
  - Electron 被纳入离线客户端判断。
  - 新增 `isLocalOfflineMode()`，离线客户端默认禁用后端持续 YOLO 检测，走本地 ONNX。
  - 新增 `resolveModelUrl()`，修复 Electron `file://` 下模型路径解析。

- `src/server/database.js`
  - 增加 `process.env.ELECTRON_USER_DATA_PATH` 判断。
  - Electron 下数据库写入用户数据目录，不写入 app 安装目录或 asar。

- `src/lib/onnxYoloDetector.ts`
  - 初始化 Worker 时使用 `resolveModelUrl()` 处理模型路径。

- `src/hooks/liveInspection/useLiveYoloDetection.ts`
  - Electron 离线模式下使用 ONNX 前端推理。
  - 桌面端推理冷却时间暂设为 `500ms`，区别于移动端 `3000ms`。

- `src/hooks/ocr/useRealtimeDetectionLoop.ts`
  - 后端 YOLO 检测开关改为基于 `isLocalOfflineMode()`。

- `src/hooks/safetyEquipment/usePPEDetection.ts`
  - PPE 检测同样区分离线客户端与后端模式。

- `src/main-mobile.tsx`
  - Electron 下使用 `HashRouter`，避免 `loadFile()` + BrowserRouter 刷新/跳转时解析到不存在的本地文件路径。
  - Electron 下不再把 `window.__IS_MOBILE_APP__` 强行设为 `true`。

- `src/lib/navigation.ts`
  - 新增桌面端路由辅助方法，Electron 下用 `file://.../index.html#/route` 打开新窗口或跳转。

- `src/server/api.js`
  - 增加 Electron 内置 API 需要的模板/配方 CRUD 路由：`ocr-keyword-templates`、`ocr-barcode-templates`、`stage-recipes`、`product-recipes`。
  - 增加 `product-recipes/:id/assign-stages/`，修复模板页/OCR 页请求到 HTML 后 JSON 解析失败的问题。

- `android-app/www/node-launcher.js`
  - 非 Capacitor 环境下延迟隐藏 loading，避免浏览器/Electron 静态调试时卡住首屏。

## 4. 当前启动与卡住问题

### 已修复现象

Electron 原先打开后可能停在：

```text
AI 智能检测系统
正在启动本地离线服务...
```

### 原始问题

`electron-app/www/index.html` 原先仍包含：

```html
<script>
  window.__IS_MOBILE_APP__ = true;
</script>
<script src="./node-launcher.js"></script>
```

这说明 Electron 当前加载的是 APK 移动端静态入口。`node-launcher.js` 在 Electron 中检测不到 `cordova`，会跳过 Node 启动并尝试隐藏 loading；但真正的 Node 服务已经由 Electron 主进程启动。这两个启动模型混在一起，容易造成 loading、服务就绪事件和前端环境判断不一致。

### 已采用修复

现在已做 Electron 专用入口，不再直接使用 APK 的 `node-launcher.js` 作为桌面启动协议：

1. 在构建/复制阶段为 Electron 生成或替换 `www/index.html`：
   - 设置 `window.__IS_ELECTRON__ = true`。
   - 设置 `window.__IS_MOBILE_APP__ = false`。
   - 设置 `window.__ELECTRON_ASSET_BASE__`，固定 `file://` 静态资源根目录。
   - 不加载 APK 的 `node-launcher.js`。
2. Electron 主进程启动 Express 后，`electron-launcher.js` 轮询 `http://127.0.0.1:5001/health`，成功后隐藏 loading。
3. `electron-app/src/server/main.js` 由 `copy-assets.js` 生成桌面端入口，日志为 `desktop-node`。
4. `src/lib/config.ts` 的 `resolveModelUrl()` 优先使用 `window.__ELECTRON_ASSET_BASE__`，避免 React 路由把 `file://` 当前路径改成 `/live-inspection` 后，模型路径错误解析成 `file:///models/*.onnx`。

## 6. Windows 打包记录

`electron-app/package.json` 当前配置：

```json
{
  "scripts": {
    "pack:win": "ELECTRON_MIRROR=https://npmmirror.com/mirrors/electron/ electron-builder --win --x64 --dir",
    "dist:win": "ELECTRON_MIRROR=https://npmmirror.com/mirrors/electron/ electron-builder --win --x64",
    "build:full": "npm run build:web && npm run copy:dist && npm run dist:win"
  },
  "build": {
    "appId": "com.wyl.inspection.desktop",
    "productName": "WYL智能检测系统",
    "win": {
      "target": ["nsis", "portable"],
      "icon": "icon.ico"
    },
    "asar": true,
    "asarUnpack": ["www/models/**/*"]
  }
}
```

注意事项：

- macOS 上可以做 Electron 开发验证，但 Windows 安装包建议在 Windows 上打。
- 当前 `ELECTRON_MIRROR=... command` 写法适合 macOS/Linux shell；Windows PowerShell 需要改成：

```powershell
$env:ELECTRON_MIRROR="https://npmmirror.com/mirrors/electron/"
npx electron-builder --win --x64
```

- 也可以后续引入 `cross-env`，让 `pack:win/dist:win` 在 Windows/macOS 下统一。
- 用户前面记录里提到 “Download Electron win32 x64 binary with loose TLS finished”，说明 Windows x64 Electron 二进制下载问题已临时绕过，但最终打包仍需要在 Windows 机器复核。

## 9. 关键判断

APK 端思路是对的：离线静态前端、本地 Node 服务、本地数据库、ONNX Runtime Web 推理。  
Electron 端不能继续完全继承 APK 启动方式。桌面端应由 Electron 主进程负责服务生命周期，renderer 只负责等待本地服务就绪和加载页面。当前 loading 卡住问题已按这个边界修复，下一步重点是 ONNX 推理闭环和 Windows 机器上的正式打包。
