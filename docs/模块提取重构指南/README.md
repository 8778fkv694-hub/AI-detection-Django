## 📏 超大页面判定标准

| 行数范围 | 等级 | 建议操作 | 紧急程度 |
|---------|------|---------|---------|
| **< 1000 行** | ✅ 正常 | 无需拆分 | - |
| **1000 - 2000 行** | ⚠️ 较大 | 可考虑拆分 | 低 |
| **2000 - 3000 行** | 🔶 大 | **建议拆分** | 中 |
| **3000 - 5000 行** | 🔴 超大 | **强烈建议拆分** | 高 |
| **> 5000 行** | 🚨 严重超大 | **立即拆分** | 最高 |

**判定标准**: **≥ 2000 行** 算超大页面

**排序原则**: 
1. **紧急程度高**（超大页面优先）
2. **复杂度低**（简单模块优先）
3. **影响面低**（风险可控优先）

## ⚠️ 重要提醒

1. **超大页面优先处理**：超过 5000 行的页面严重影响开发效率，应优先拆分
2. **从简单到复杂**：先处理复杂度低的模块，积累经验后再处理复杂模块
3. **不要一次性提取所有模块**：按优先级逐步提取
4. **充分测试**：每个模块提取后都要充分测试
5. **保留原代码**：提取时先注释，确认无误后再删除
6. **文档更新**：提取后及时更新相关文档
7. **代码审查**：重要模块提取后进行代码审查
8. **新功能零代码增长**：添加新功能时，优先复用、配置、组合、替换，而不是堆积代码（参见 06 文档）
