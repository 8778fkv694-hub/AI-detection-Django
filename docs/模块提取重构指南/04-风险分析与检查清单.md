## ⚠️ 风险分析

### CSV 导出工具 (`csvExporter.ts`)

#### 风险点

1. **CSV 格式差异**
   - 风险：不同页面需要不同的列
   - 影响：中等
   - 解决方案：使用配置对象，支持自定义列映射

2. **字段映射差异**
   - 风险：有些页面需要 `ocrResult`，有些不需要
   - 影响：低
   - 解决方案：通过 `getRowData` 函数自定义字段提取

3. **文件名格式**
   - 风险：文件名前缀不同
   - 影响：低
   - 解决方案：作为配置参数传入

#### 风险等级：🟢 低

**原因**：
- 逻辑简单，依赖少
- 不影响核心功能
- 容易测试和验证
- 容易回滚

---

### YOLO 检测 Hook (`useYoloDetection.ts`)

#### 风险点

1. **状态依赖过多**
   - 风险：依赖 15+ 个状态和 setter
   - 影响：高
   - 解决方案：使用配置对象封装，通过回调处理状态更新

2. **抓拍逻辑差异**
   - 风险：不同页面的抓拍逻辑完全不同
   - 影响：高
   - 解决方案：Hook 只负责检测，抓拍逻辑通过回调传入

3. **图像处理函数依赖**
   - 风险：依赖 `compressImage`, `cropImageToROI` 等外部函数
   - 影响：中
   - 解决方案：通过参数传入这些函数

4. **检测结果处理差异**
   - 风险：不同页面处理检测结果的方式不同
   - 影响：中
   - 解决方案：通过回调函数处理检测结果

#### 风险等级：🟡 中

**原因**：
- 核心功能，影响面大
- 状态依赖复杂
- 需要充分测试

**建议**：
- 分阶段提取：先提取纯检测逻辑，抓拍逻辑保留在页面
- 充分测试每个使用该 Hook 的页面

### 摄像头管理 Hook (`useCamera.ts`)

#### 风险点

1. **状态管理不一致**
   - 风险：不同页面使用不同的状态管理方式
   - 影响：高
   - 解决方案：统一接口，通过参数传入状态 setter

2. **依赖的 Ref 和外部实例**
   - 风险：需要访问多个 ref（videoRef, streamPlayerRef, hlsPlayerRef）
   - 影响：高
   - 解决方案：通过参数传入所有必需的 ref

3. **回调函数差异**
   - 风险：不同页面的回调行为不同
   - 影响：中
   - 解决方案：通过配置对象传入回调函数

4. **设备列表变量名不一致**
   - 风险：`availableDevices` vs `videoDevices`
   - 影响：低
   - 解决方案：统一变量名，或在 Hook 内部管理

5. **物理摄像头约束配置不同**
   - 风险：约束配置略有差异
   - 影响：低
   - 解决方案：通过配置对象传入约束参数

#### 风险等级：🔴 高

**原因**：
- 复杂度最高
- 依赖最多
- 影响面最广
- 错误处理复杂

**建议**：
- 最后提取
- 分步提取：先提取物理摄像头，再提取流媒体
- 充分测试每个使用场景

## ❓ 常见问题

### Q1: 如何决定哪些代码应该提取？

**A**: 遵循以下原则：
1. **重复度**：3个以上文件有相同代码
2. **复杂度**：代码逻辑复杂，值得复用
3. **独立性**：功能相对独立，依赖少
4. **维护性**：提取后更容易维护

### Q2: 如何处理不同页面的差异？

**A**: 使用以下策略：
1. **配置对象**：通过配置参数处理差异
2. **回调函数**：页面特定逻辑通过回调传入
3. **预设配置**：为常见场景提供预设
4. **可选参数**：非必需功能作为可选参数

### Q3: 提取后如何测试？

**A**: 测试步骤：
1. **单元测试**：测试提取的模块本身
2. **集成测试**：测试模块在页面中的使用
3. **功能测试**：测试完整功能流程
4. **回归测试**：确保没有破坏现有功能

### Q4: 如果提取后出现问题怎么办？

**A**: 回滚策略：
1. **保留原代码**：提取时先注释原代码，不删除
2. **版本控制**：提交前创建分支
3. **逐步迁移**：一个页面一个页面迁移
4. **快速回滚**：出问题时可以快速恢复

### Q5: 如何确保类型安全？

**A**: 类型安全措施：
1. **严格类型**：避免使用 `any`
2. **接口定义**：为所有配置对象定义接口
3. **类型检查**：启用 TypeScript 严格模式
4. **类型测试**：确保类型推断正确

### Q6: 性能会受影响吗？

**A**: 性能考虑：
1. **避免过度抽象**：不要为了提取而提取
2. **使用 useCallback/useMemo**：避免不必要的重新计算
3. **优化依赖数组**：减少不必要的重新渲染
4. **性能测试**：提取前后对比性能
