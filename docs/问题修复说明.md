# 问题修复说明

## 修复的问题

### 1. Ollama服务启动失败
**问题**: 本地模型服务无法启动，导致429错误
**解决方案**:
- Ollama 启动入口已收口到 `start_mac.sh ollama`
- Ollama 代理入口已收口到 `start_mac.sh ollama-proxy`

### 2. 后端检测频繁出现429错误
**问题**: 系统繁忙，请求过于频繁
**解决方案**:
- 将实时检测频率从1秒改为3秒，减少API调用频率
- 优化API重试机制，429错误等待3秒，其他错误等待2秒
- 增加更智能的重试延迟策略

### 3. HTTPS页面无法访问HTTP的Ollama服务
**问题**: 混合内容安全策略阻止HTTPS页面访问HTTP服务
**解决方案**:
- 创建了 `ollama-proxy.js` HTTPS代理服务器
- 代理服务运行在 `https://localhost:11435`
- 更新了 `LocalModelScreen.tsx` 使用HTTPS代理

## 使用方法

### 启动Ollama服务（推荐）
```bash
# 启动Ollama服务及HTTPS代理
./start_mac.sh ollama-proxy
```

### 仅启动Ollama服务
```bash
# 仅启动Ollama服务
./start_mac.sh ollama
```

### 手动启动代理服务
```bash
# 安装依赖
npm install express cors http-proxy-middleware

# 启动代理服务
node ollama-proxy.js
```

## 服务地址

- **Ollama服务**: `http://localhost:11434`
- **HTTPS代理**: `https://localhost:11435`
- **聊天接口**: `https://localhost:11435/api/chat`
- **模型列表**: `https://localhost:11435/api/tags`

## 优化效果

1. **减少429错误**: 实时检测频率降低，API调用更合理
2. **解决CORS问题**: HTTPS页面可以正常访问本地模型
3. **提高稳定性**: 更好的错误处理和重试机制
4. **简化部署**: 一键启动脚本，减少手动配置

## 注意事项

1. 确保已安装Ollama: `brew install ollama` (macOS)
2. 确保已安装Node.js和npm
3. 首次使用需要拉取模型: `ollama pull qwen2.5-vl:7b`
4. 代理服务需要HTTPS证书，如果遇到证书问题，可以临时使用HTTP

## 故障排除

### Ollama服务启动失败
```bash
# 检查Ollama是否安装
ollama --version

# 手动启动Ollama
ollama serve

# 检查服务状态
curl http://localhost:11434/api/tags
```

### 代理服务启动失败
```bash
# 检查端口是否被占用
lsof -i :11435

# 安装依赖
npm install express cors http-proxy-middleware

# 手动启动代理
node ollama-proxy.js
```

### 仍然出现429错误
1. 检查后端服务是否正常运行
2. 增加检测间隔时间
3. 检查网络连接和服务器负载
