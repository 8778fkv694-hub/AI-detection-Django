# 检测队列问题解决方案

## 问题描述

在实时检测场景中，当检测间隔设置过短（如0.1秒）而API响应时间较长（如0.2秒）时，会产生以下问题：

1. **请求堆积** - 新请求在旧请求完成前就发出，导致队列增长
2. **资源浪费** - 处理过期帧，结果已无意义
3. **内存泄漏** - 大量未完成的Promise占用内存
4. **响应延迟** - 用户看到的检测结果滞后于实际画面

## 当前已实现的机制

### 1. 检测锁 (isDetectingRef)
```typescript
// src/screens/OCRDetectionScreen.tsx
const isDetectingRef = useRef<boolean>(false);

if (isDetectingRef.current) {
  return; // 跳过，上一次检测尚未完成
}
isDetectingRef.current = true;
// ... 执行检测
isDetectingRef.current = false;
```
**作用**：防止同一时间多个检测并发执行

### 2. API请求锁 (isRequestInProgress)
```typescript
// src/lib/api.ts
let isRequestInProgress = false;

if (isRequestInProgress) {
  return []; // 返回空结果，跳过此次请求
}
isRequestInProgress = true;
// ... 执行API请求
isRequestInProgress = false;
```
**作用**：防止API层面的并发请求

### 3. 队列处理锁 (isProcessingQueueRef)
```typescript
// src/hooks/ocr/useRealtimeDetection.ts
if (isProcessingQueueRef.current || isDetectingRef.current) {
  return;
}
```
**作用**：防止队列处理过程中的重入

### 4. 自适应检测间隔 (已实现)
```typescript
if (detectionInterval === 0) {
  // 检测完成后立即触发下一次
  const runAdaptive = async () => {
    await performRealtimeDetectionRef.current?.();
    setTimeout(runAdaptive, 10);
  };
  runAdaptive();
}
```
**作用**：根据实际API响应时间自动调整检测频率

## 进一步优化方案

### 方案1: 请求取消机制 (AbortController)

**原理**：当新请求发出时，取消上一个未完成的请求

```typescript
// 在组件中维护AbortController
const abortControllerRef = useRef<AbortController | null>(null);

const performDetection = async () => {
  // 取消上一个请求
  if (abortControllerRef.current) {
    abortControllerRef.current.abort();
  }

  // 创建新的AbortController
  abortControllerRef.current = new AbortController();

  try {
    const result = await yoloDetectBackend(imageBase64, conf, {
      signal: abortControllerRef.current.signal
    });
    // 处理结果
  } catch (error) {
    if (error.name === 'AbortError') {
      // 请求被取消，忽略
      return;
    }
    throw error;
  }
};
```

**优点**：
- 始终只有一个活跃请求
- 节省服务器资源
- 结果始终是最新帧

**缺点**：
- 需要修改API层支持signal参数
- 可能丢失中间帧的检测结果

### 方案2: 最新帧优先队列

**原理**：只保留最新的待检测帧，丢弃旧帧

```typescript
const latestFrameRef = useRef<string | null>(null);
const isProcessingRef = useRef(false);

const queueDetection = (frameBase64: string) => {
  // 始终更新为最新帧
  latestFrameRef.current = frameBase64;

  // 如果没有正在处理，启动处理
  if (!isProcessingRef.current) {
    processQueue();
  }
};

const processQueue = async () => {
  while (latestFrameRef.current) {
    isProcessingRef.current = true;
    const frame = latestFrameRef.current;
    latestFrameRef.current = null; // 清空，准备接收新帧

    await performDetection(frame);
  }
  isProcessingRef.current = false;
};
```

**优点**：
- 内存占用恒定（只保存1帧）
- 检测结果始终接近最新
- 实现简单

**缺点**：
- 会丢失中间帧

### 方案3: 滑动窗口限流

**原理**：限制单位时间内的最大请求数

```typescript
const requestTimestamps: number[] = [];
const MAX_REQUESTS_PER_SECOND = 5;

const canMakeRequest = (): boolean => {
  const now = Date.now();
  // 移除1秒前的记录
  while (requestTimestamps.length > 0 && requestTimestamps[0] < now - 1000) {
    requestTimestamps.shift();
  }
  return requestTimestamps.length < MAX_REQUESTS_PER_SECOND;
};

const performDetection = async () => {
  if (!canMakeRequest()) {
    return; // 达到限流阈值，跳过
  }
  requestTimestamps.push(Date.now());
  // 执行检测...
};
```

**优点**：
- 保护服务器不被过载
- 可配置的限流策略

**缺点**：
- 可能跳过有效帧

### 方案4: 服务端批处理

**原理**：客户端累积多帧，一次性发送给服务端处理

```typescript
// 客户端
const frameBuffer: string[] = [];
const BATCH_SIZE = 3;
const BATCH_INTERVAL = 500; // ms

const addFrame = (frame: string) => {
  frameBuffer.push(frame);
  if (frameBuffer.length >= BATCH_SIZE) {
    sendBatch();
  }
};

const sendBatch = async () => {
  const frames = frameBuffer.splice(0, BATCH_SIZE);
  const results = await batchDetect(frames);
  // 处理批量结果...
};

// 服务端需要支持批量检测API
// POST /results/yolo-detect-batch/
// Body: { images: [base64_1, base64_2, ...] }
```

**优点**：
- 减少HTTP开销
- 服务端可并行处理
- 更高的吞吐量

**缺点**：
- 需要修改服务端API
- 增加响应延迟

### 方案5: WebSocket实时通道

**原理**：使用WebSocket替代HTTP轮询

```typescript
// 客户端
const ws = new WebSocket('ws://server/detection');

ws.onmessage = (event) => {
  const result = JSON.parse(event.data);
  handleDetectionResult(result);
};

const sendFrame = (frameBase64: string) => {
  ws.send(JSON.stringify({ image: frameBase64 }));
};

// 服务端 (Django Channels)
class DetectionConsumer(AsyncWebsocketConsumer):
    async def receive(self, text_data):
        data = json.loads(text_data)
        result = await self.detect(data['image'])
        await self.send(json.dumps(result))
```

**优点**：
- 真正的实时通信
- 无HTTP开销
- 服务端可主动推送

**缺点**：
- 需要WebSocket基础设施
- 连接管理复杂
