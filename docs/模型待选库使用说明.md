# 模型待选库使用说明

> **核心理念**: 先建立待选库，再激活使用

---

## 📋 核心概念

### 1. 待选库（Standby Pool）

**定义**: 用户选择的可用模型集合，处于**待选状态**

**特点**:
- 存储在浏览器本地（localStorage）
- 可随时添加/移除模型
- 不会立即激活模型

**比喻**: 像是"收藏夹"或"快捷工具栏"，把常用的模型收集起来

---

### 2. 激活模型（Active Model）

**定义**: 当前正在使用的YOLO检测模型

**特点**:
- 从待选库中选择
- 调用后端API切换
- 立即生效，影响所有检测操作

**比喻**: 从工具栏中选中一个工具开始使用

---

## 🔄 完整工作流程

```
第1步: 模型管理页面
  ↓
【浏览所有YOLO模型】
  ↓
【勾选需要的模型】(可多选)
  ↓
【点击"加入待选库"】
  ↓
待选库已更新 ✅


第2步: 检测页面
  ↓
【打开模型选择器下拉框】
  ↓
【看到待选库中的模型列表】
  ↓
【选择一个模型】
  ↓
【后端API切换模型】
  ↓
模型已激活 ✅
检测目标自动更新 ✅
```

---

## 📖 详细操作步骤

### 步骤 1: 将模型加入待选库

1. **打开模型管理页面**
   - 点击导航栏的"模型管理"

2. **选择模型**
   - 浏览"PPE检测模型"列表
   - 勾选需要的模型（可多选）
   - 或点击"全选"快速选择所有模型

3. **加入待选库**
   - 点击右上角"加入待选库 (N)"按钮
   - 看到提示：✅ "已添加 N 个模型到待选库"

4. **验证**
   - 已加入的模型显示"已在待选库"徽章
   - 右上角显示"待选库: N"

---

### 步骤 2: 在检测页面激活模型

1. **打开检测页面**
   - OCR检测页面
   - 实时检测页面
   - 齐套化检测页面

2. **找到模型选择器**
   - 在设置面板中找到"YOLO 检测模型"下拉框
   - 显示当前激活的模型和待选数量

3. **激活模型**
   - 点击下拉框
   - 从待选库中选择模型
   - 等待切换（显示"切换中..."）
   - 看到提示：✅ "已激活模型: XXX"

4. **验证**
   - 检测目标自动更新为新模型的类别
   - 当前模型显示为刚选择的模型

## 🎯 实际使用场景

### 场景 1: 初次使用

**目标**: 设置常用的检测模型

```
1. 打开"模型管理"页面
2. 选择以下模型并加入待选库:
   ✅ PPE检测模型（洁净室）
   ✅ 洁净用品检测模型
   ✅ 齐套化检测模型
3. 完成！现在可以在任何检测页面快速切换了
```

---

### 场景 2: 切换检测场景

**目标**: 从PPE检测切换到洁净用品检测

```
当前: 使用"PPE检测模型"检测人员穿戴

需要: 改为检测洁净用品

操作:
1. 在检测页面打开"YOLO 检测模型"下拉框
2. 选择"洁净用品检测模型"
3. 模型立即切换
4. 检测目标自动变为: mop, bucket, cleaner等
5. 开始检测洁净用品 ✅
```

---

### 场景 3: 管理待选库

**目标**: 移除不常用的模型

```
1. 打开"模型管理"页面
2. 找到已标记"已在待选库"的模型
3. 取消勾选
4. 点击... (目前暂不支持批量移除，需要单独调用removeFromPool)

或者:
- 在代码中调用 `removeFromPool(modelId)` 移除
- 或使用 `clearPool()` 清空整个待选库
```

## 💡 设计优势

### 1. 概念清晰

| 操作 | 位置 | 效果 | 是否调用后端API |
|------|------|------|----------------|
| **加入待选库** | 模型管理页面 | 添加到本地列表 | ❌ 否 |
| **激活模型** | 检测页面 | 切换当前模型 | ✅ 是 |

### 2. 用户体验好

- **模型管理页面**: 一次性配置，批量添加
- **检测页面**: 快速切换，无需离开页面
- **待选库**: 只显示常用模型，避免选择困难

### 3. 性能优化

- 待选库存储在本地，无需每次加载所有模型
- 只有激活时才调用API，减少网络请求
- 跨页面共享待选库，状态一致

## 🔧 技术说明

### 数据存储

**localStorage Key**: `model_pool_v1`

**数据结构**:
```json
[
  {
    "id": "ppe_detection",
    "name": "PPE检测模型",
    "description": "洁净室环境和个人防护装备检测",
    "detection_type": "PPE"
  },
  {
    "id": "cleaning_detection",
    "name": "洁净用品检测模型",
    "description": "检测清洁工具和用品",
    "detection_type": "Cleaning"
  }
]
```

### 状态同步

- **初始化**: 从localStorage加载 + 从后端获取当前激活模型
- **添加模型**: 更新localStorage
- **激活模型**: 调用API + 更新localStorage
- **跨页面**: 所有检测页面共享同一个待选库

### API调用

**激活模型时调用**:
```typescript
POST /results/switch-model/
{
  "model_id": "ppe_detection"
}

响应:
{
  "message": "模型切换成功",
  "current_model": "ppe_detection",
  "model_id": "ppe_detection"
}
```

## ❓ 常见问题

### Q1: 待选库的模型会自动同步到其他设备吗？

**A**: 不会。待选库存储在浏览器本地（localStorage），仅在当前浏览器有效。
  - 优点: 每个设备可以有不同的常用模型
  - 缺点: 更换设备需要重新配置

### Q2: 可以在检测页面直接添加模型到待选库吗？

**A**: 目前不支持。需要在"模型管理"页面添加。
  - 原因: 统一管理，避免页面功能过载
  - 建议: 初次使用时一次性配置好常用模型

### Q3: 待选库为空时会怎样？

**A**: 检测页面的模型选择器会显示提示：
  > "暂无待选模型，请先在模型管理页面将模型加入待选库"

  点击"模型管理"链接可快速跳转。

### Q4: 激活模型失败怎么办？

**A**: 可能原因和解决方案：
  1. **网络问题**: 检查网络连接，重试
  2. **模型不存在**: 确认模型文件存在于后端
  3. **后端服务未启动**: 检查Django服务状态
  4. **权限问题**: 检查API权限配置

### Q5: 待选库和收藏夹有什么区别？

**A**:
  - **待选库**: 临时选择的可用模型集合，可随时修改
  - **收藏夹**: (未实现) 可能用于长期保存的模型配置
