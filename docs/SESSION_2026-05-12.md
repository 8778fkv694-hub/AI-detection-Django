# 2026-05-12 修改总结：macOS 本地验证 + 推流健壮性 + 清晰度可见性

> 目标：macOS 上能跑完整检测流水线、推流模块不再翻车、清晰度计算可观测。

---

## 一、核心修复：macOS 物理摄像头也能 YOLO 检测

**根因**：前端把浏览器 `deviceId`（UUID）当作后端 `stream_id`（DB 主键）传给 `/detections/` API。后端找不到对应的 StreamSource，检测循环永远拿不到帧。

### 修改文件

**`src/screens/OCRDetectionScreen.tsx`** — 区分物理/虚拟摄像头
```typescript
// 虚拟摄像头 selectedDeviceId = "stream-<id>"，物理摄像头 = 浏览器 UUID
const backendStreamId = selectedDeviceId?.startsWith('stream-')
  ? selectedDeviceId.replace('stream-', '')
  : null;
```
传给 `useRealtimeDetectionLoop` 的是 `backendStreamId`，不是 `selectedDeviceId`。

**`src/screens/LiveInspectionScreen.tsx`** — 同上修复。

**`src/hooks/ocr/useRealtimeDetectionLoop.ts`** — 3 处 `fetch(/streams/${streamId}/...)` 增加 `&& streamId` 守卫。`streamId` 为 null 时自动回退传统模式（前端截图 + yoloDetectBackend）。

**`src/hooks/ocr/useRealtimeDetectionLoop.ts`** — `batchExtractROIs` 调用的 `!useBackendDetection` 守卫移除。物理摄像头时也积累 ROI。

### 效果

| | 修复前 | 修复后 |
|---|---|---|
| macOS 物理摄像头 (OBS/iPhone/内置) | YOLO 检测不工作，404 报错 | 走传统模式，功能等价 Jetson |
| Jetson 虚拟摄像头 (stream-前缀) | streamId 带前缀不匹配 | 正确提取 DB 主键 |

## 二、后端：MJPEG 推流健壮性

### 2.1 生成器心跳看门狗

**文件**：`backend/inspection/mjpeg_view.py`

**问题**：`_read_loop` 线程卡住或流断开后，`_mjpeg_generator` 空转不休，永久占住 Django worker 线程。

**修复**：新增 10 秒心跳检测。

```python
last_new_frame_time = time.time()
FRAME_TIMEOUT = 10.0

while reader.is_running:
    if time.time() - last_new_frame_time > FRAME_TIMEOUT:
        logger.warning("no new frames for %.0fs, stream appears dead", FRAME_TIMEOUT)
        break  # 主动退出，释放 worker
    # ...
    if version != last_seen_id:
        last_new_frame_time = time.time()  # 拿到新帧，重置心跳
```

### 2.2 /detections/ API 不再返回 404

**文件**：`backend/inspection/detection_api.py`

**问题**：检测循环未启动时返回 HTTP 404，前端轮询导致浏览器控制台红色刷屏。

**修复**：暂无数据时返回 `200 { stream_id, boxes: [], detect_fps: 0 }`，不再返回 404。

## 三、前端：MJPEG 流断连自动重连

**文件**：`src/lib/mjpegPlayer.ts`

**问题**：`<img>` 标签消费 MJPEG multipart 流，网络闪断或后端重启后，`onerror` 直接 `stop()` + 报错，画面永久卡死。

**修复**：新增 `_handleStreamError()` 重连机制。

```
流断开 → img.onerror → _handleStreamError()
  ├─ 尝试 1 (1s 后): mjpegImg.src = url  // 重新发起 MJPEG 连接
  ├─ 尝试 2 (2s 后): mjpegImg.src = url
  ├─ 尝试 3 (3s 后): mjpegImg.src = url
  └─ 3 次失败 → stop() + onError 通知上层
```

成功重连时自动重置计数器。

## 五、模型切换时自动更新检测目标

**文件**：`src/hooks/ocr/useModelConfig.ts`、`src/screens/OCRDetectionScreen.tsx`

**问题**：先选配方再换模型时，旧配方的 targets 部分在新模型中仍有效，导致 targets 不更新。

**修复**：
1. 手动切换模型 → 自动全选新模型的所有可用目标
2. 配方应用时设置 `suppressAutoSelectRef.current = true`，跳过自动全选（配方自己指定目标）
3. 首次加载时保留持久化的有效目标（不影响之前的行为）

## 六、全局视频流显示设置

**新增文件**：
- `src/state/streamSettingsStore.ts` — Zustand 持久化 store
- `src/components/StreamSettingsPopover.tsx` — 侧边栏弹窗 UI

**修改文件**：
- `src/App.tsx` — 侧边栏底部添加设置入口
- `src/hooks/ocr/useOCRCamera.ts` — MJPEG 读取全局 fps/quality/width
- `src/hooks/liveInspection/useLiveCamera.ts` — HLS/StreamPlayer 读取全局 fps/quality/width

### 设置项

| 参数 | 范围 | 默认 | 说明 |
|------|------|------|------|
| 显示帧率 | 5-30 fps | 12 | 降低减少浏览器解码压力 |
| JPEG 质量 | 30-100% | 75 | 降低减少带宽和体积 |
| 显示宽度 | 320-1920px | 960 | 降低减少解码分辨率 |

**不影响检测精度**。设置只改 MJPEG URL 查询参数（`?fps=&quality=&width=`），后端 `detection_loop` 从 `StreamReader` 取原始分辨率帧做 YOLO 推理。

### Jetson 建议值

`8fps / 50% / 640px` — 显著降低浏览器 CPU（JPEG 解码在 ARM 小核上纯软件执行）。
