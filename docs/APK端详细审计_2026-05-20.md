# APK 端详细审计记录

> 更新时间：2026-05-20  
> 审计对象：`android-app/` APK 离线客户端  
> 当前结论：debug APK 可在 macOS 构建成功，核心静态资源、内置 Node 服务、LowDB 种子、WASM、ONNX、`.pt` 模型均已打入 APK；本机无 Android 设备，未完成真机安装/启动验证。

---

## 1. 总体结论

APK 端目前采用的架构是：

- 壳层：Capacitor Android WebView。
- 前端：`npm run build:mobile` 生成 `android-app/www/dist`。
- 启动器：`android-app/www/node-launcher.js` 在 `deviceready` 后启动 `nodejs-mobile-cordova`。
- 本地服务：`android-app/www/nodejs-project/main.js` 启动 Express，监听 `0.0.0.0:5001`。
- 前端 API：移动端环境默认访问 `http://127.0.0.1:5001/api`。
- 数据库：LowDB 写入 `cordova.app.datadir()/persistent_data/db/db.json`。
- 推理：
  - 前端 ONNX Runtime Web 负责端侧 ONNX 推理。
  - 内置 Node API 当前不直接执行 `.pt` 推理，`.pt` 主要用于模型管理、文件存在性与后续原生推理扩展。

本轮实际跑通了 `bash scripts/build-apk.sh debug`，输出：

```text

大小：1.2G
Gradle：BUILD SUCCESSFUL
```

## 2. 构建入口审计

### 正式 APK 构建入口

正式打包应使用：

```bash
cd android-app
bash scripts/build-apk.sh debug
```

或：

```bash
cd android-app
bash scripts/build-apk.sh release
```

`scripts/build-apk.sh` 会执行完整流程：

1. `npm run build:mobile`
2. 复制 ONNX Runtime WASM 到 `www/dist`
3. 同步 `src/server/api.js`、`src/server/database.js` 到 `www/nodejs-project`
4. 复制 `data/db.json` 为 `db-seed.json`
5. `npm install` 内置 Node 依赖
6. `npx cap sync android`
7. 修复 `NodeJS.java` 的 `PROJECT_ROOT`
8. 替换 Gradle nodejs-mobile patch
9. 解压/整理 `libnode.so`
10. 同步 `nodejs-project` 到 Android assets
11. 同步 `.pt` 和 `.onnx` 模型
12. 执行 Gradle `assembleDebug` 或 `assembleRelease`

### 注意：不要只用 `build:full`

`android-app/package.json` 的：

```json
"build:full": "npm run build:web && npm run cap:sync"
```

只同步前端 WebView 资源，不会完成以下关键步骤：

- 不会复制内置 Node 服务到最终 assets。
- 不会复制 `.pt` 模型。
- 不会复制 `.onnx` 到 `assets/public/models`。
- 不会修复 `NodeJS.java` 路径。
- 不会处理 nodejs-mobile Gradle 兼容补丁。

所以后续正式 APK 打包必须以 `scripts/build-apk.sh` 为准。

## 3. 启动链路审计

APK 启动顺序：

```text
Android Activity
  -> Capacitor WebView 加载 assets/public/index.html
  -> index.html 设置 window.__IS_MOBILE_APP__ = true
  -> node-launcher.js 等待 deviceready
  -> window.nodejs.start('main.js')
  -> nodejs-project/main.js 启动 Express :5001
  -> Node 发送 server-ready
  -> node-launcher.js 轮询 /health
  -> 设置 window.__NODE_SERVER_READY = true
  -> 派发 node-server-ready
  -> src/main-mobile.tsx 挂载 React
```

审计结果：

- `node-launcher.js` 在非 Capacitor 环境会跳过 Node 启动并隐藏 loading，方便浏览器/Electron 静态调试。
- APK 环境下 React 会等待 `node-server-ready`，避免服务未起好时先发 API 请求。
- 45 秒兜底挂载仍保留。若真机长期卡 loading，应优先看 `nodejs-mobile` 是否启动失败、`/health` 是否可达。

## 5. API 与数据库

### API 基址

`src/lib/config.ts` 中移动端离线客户端会自动使用：

```text
http://127.0.0.1:5001/api
```

本机烟测已验证：

```text
GET /health -> 200
GET /api/results/available-models/ -> 200
GET /api/results/ppe-model-status/ -> 200
GET /api/stage-recipes/ -> 200
```

### 本轮修复：旧 seed 不补新集合

发现问题：

`data/db.json` 旧种子只有：

```json
{
  "results": [],
  "standards": [],
  "modelVersions": [],
  "ppeModelStatus": {}
}
```

但当前 API 已需要：

- `ocrKeywordTemplates`
- `ocrBarcodeTemplates`
- `productRecipes`
- `stageRecipes`

旧逻辑只在 `results` 不存在时才 `db.defaults(defaultData).write()`。由于旧 seed 已有 `results`，APK 首次启动不会补齐新集合。

已修复：

- `src/server/database.js` 改为每次启动都执行 `db.defaults(defaultData).write()`，自动补齐缺失集合。
- `data/db.json` 已补齐新集合。
- 重新打包后，APK 内 `assets/public/nodejs-project/src/server/db-seed.json` 已包含新集合。

### 体积风险

debug APK 当前约 `1.2G`。主要来源：

- 四架构 `libnode.so` 合计约 145MB。
- `.pt` 模型约 400MB。
- `.onnx` 模型约 354MB。
- 前端、WASM、Node 依赖及 Gradle debug 开销。

后续如果面向现场分发，建议：

- 只保留 `arm64-v8a` ABI。
- 确认 APK 是否真的需要同时内置 `.pt` 和 `.onnx`。
- `ppe_large.onnx` 若暂不用，可从 APK 打包清单剔除。
- release 包再评估体积。

## 7. Gradle 与 nodejs-mobile

关键配置：

- `android-app/android/app/build.gradle`
  - `minSdkVersion = 22`
  - `targetSdkVersion = 34`
  - `noCompress 'onnx', 'wasm'`
- `android-app/scripts/nodejs-mobile-cordova-capacitor.gradle`
  - 负责兼容 Capacitor assets 目录。
  - 当前仍默认构建/携带四个 ABI。
- `NodeJS.java`
  - 已由构建脚本修正为：

```text
PROJECT_ROOT = "public/nodejs-project"
BUILTIN_ASSETS = "builtin_modules"
```

构建警告：

- `flatDir should be avoided`：非阻断，来自 Android 依赖方式。
- SDK XML version 4 warning：非阻断，命令行工具与 Android Studio 版本不完全一致。
- CMake `No project() command`：非阻断，来自 nodejs-mobile 插件 CMakeLists。
- Gradle deprecated features：非阻断，未来 Gradle 9 需处理。

## 9. 当前风险清单

### P0/P1

- 真机未验证。macOS 构建成功不等于 Android WebView 运行时完全成功。
- APK 体积过大，1.2G 可能影响安装、分发和现场升级。
- `build:full` 与正式打包流程含义不一致，后续容易误用。

### P2

- 移动端 `window.open()` 在 Android WebView 中可能表现为无新窗口或系统浏览器行为，需真机确认。
- 内置 Node API 的 `.pt` 推理接口当前返回 501，真正端侧实时推理依赖前端 ONNX。
- `allowMixedContent` 和 `cleartext` 当前为本地服务/调试服务放开，生产可继续收紧范围。
- Gradle/nodejs-mobile 插件有多处兼容性补丁，后续 Capacitor update 后必须复查。

### P3

- 前端日志较多，真机 logcat 调试时可能淹没错误。
- Vite bundle 偏大，可后续拆分 OCR、批量检测、帮助页等非首屏模块。

## 10. 下次继续建议

1. 找 Android 真机或平板执行：

```bash

adb logcat | rg "NodeLauncher|mobile-node|Database|Capacitor|chromium|ONNX|YoloWorker"
```

2. 真机首屏检查：

- loading 是否在 Node `/health` 成功后消失；
- `node-server-ready` 是否触发；
- API 是否走 `127.0.0.1:5001`；
- 模型管理页是否显示模型 `exists=true`；
- 模版/OCR/配方页面是否无 JSON 解析错误。

3. 真机检测页检查：

- 摄像头权限；
- 预览是否黑屏；
- ONNX 模型是否能加载；
- 推理耗时是否可接受；
- 3 秒冷却策略是否足够流畅；
- 抓拍结果是否能保存到 LowDB。

4. 体积优化优先级：

- 先只保留 `arm64-v8a`；
- 再决定是否保留 `.pt`；
- 最后决定是否移除 `ppe_large.onnx`。

5. 构建入口统一：

- 后续建议把 `android-app/package.json` 的 `build:full` 改名或改成调用 `scripts/build-apk.sh`，避免误以为 `cap sync` 就是完整 APK 打包。
