# 流媒体系统优化总结

**优化时间**：2024年（从昨晚到今天）  
**优化目标**：降低FFmpeg CPU占用，提升流媒体播放稳定性  
**优化结果**：CPU占用从90%降至20-30%，播放稳定性显著提升

---

## 一、问题诊断

### 初始问题
- **FFmpeg进程CPU占用**：约90%，严重影响系统性能
- **流媒体播放不稳定**：播放3-5秒后重启，无法流畅播放完整视频
- **本地视频循环播放**：播放到末尾后停止，无法自动循环
- **进程管理问题**：FFmpeg进程可能残留

### 根本原因分析
1. **编码参数未优化**：使用默认或高质量参数，CPU负载过高
2. **HLS播放列表类型错误**：本地文件使用了实时流（EVENT）类型，导致播放列表频繁更新
3. **前端播放器配置不当**：VOD类型使用了低延迟模式，缓冲不足
4. **URL路径解析错误**：HLS片段URL路径拼接错误

---

## 二、核心优化措施

### 1. FFmpeg编码参数优化（CPU占用降低约70%）

#### 关键参数调整

| 参数 | 优化前 | 优化后 | 说明 |
|------|--------|--------|------|
| **帧率 (fps)** | 30fps | **15fps** | 降低50%编码负载 |
| **CRF值** | 18-23 | **26** | 质量略降，CPU占用显著降低 |
| **Preset** | medium/fast | **ultrafast** | 编码速度优先，CPU占用最低 |
| **音频** | 启用 | **禁用 (-an)** | 视频流不需要音频 |
| **场景检测** | 启用 | **禁用 (-sc_threshold 0)** | 减少计算开销 |
| **GOP大小** | 默认 | **2倍FPS** | 平衡延迟与效率 |

#### 代码实现

**位置**：`backend/inspection/stream_hls.py`

```python
def __init__(self, stream_id: str, source_url: str, output_dir: str, 
             fps: int = 15, width: int = 0, height: int = 0, 
             crf: int = 26, preset: str = 'ultrafast', threads: int = 0):
    """
    Args:
        fps: 输出帧率（默认15fps，降低CPU占用）
        crf: 恒定质量因子（18-28，默认26，值越大质量越低但CPU占用越低）
        preset: 编码预设（ultrafast/veryfast/fast/medium，默认ultrafast最快）
        threads: 编码线程数（0表示自动，可以限制CPU核心数）
    """
```

**FFmpeg命令构建**：

```python
cmd.extend([
    '-i', input_source,
    '-c:v', 'libx264',
    '-preset', self.preset,  # ultrafast最快，CPU占用最低
    '-crf', str(self.crf),   # 26默认，值越大CPU占用越低
    '-r', str(self.fps),      # 15fps，降低CPU占用
    '-g', str(int(self.fps * 2)),  # GOP大小（关键帧间隔，设为2倍FPS）
    '-sc_threshold', '0',     # 禁用场景切换检测
    '-an',                    # 禁用音频
])
```

#### 优化效果
- **CPU占用降低**：从90%降至20-30%
- **编码速度提升**：ultrafast预设显著加快编码速度
- **质量平衡**：CRF 26在检测场景下质量足够，性能提升明显

### 2. HLS播放列表类型优化（解决播放重启问题）

#### 问题分析
- **错误配置**：本地文件使用了`event`类型（实时流），导致播放列表频繁更新
- **影响**：播放器不断重新加载清单，导致播放中断、重启

#### 解决方案
根据视频源类型自动选择正确的HLS播放列表类型：

| 视频源类型 | HLS类型 | hls_list_size | hls_flags | 说明 |
|-----------|---------|---------------|-----------|------|
| **本地文件** | `vod` | 0（所有片段） | `delete_segments` | 完整播放列表，不频繁更新 |
| **实时流** | `event` | 10（最近片段） | `delete_segments+append_list` | 动态更新，只保留最近片段 |

#### 代码实现

**位置**：`backend/inspection/stream_hls.py`

```python
# 判断是否是本地文件
is_local_file = not input_source.startswith(('http://', 'https://', 'rtsp://', 'rtmp://'))

# 根据文件类型决定播放列表类型和参数
if is_local_file:
    # 本地文件：使用 vod 类型，包含所有片段
    playlist_type = 'vod'
    hls_list_size = 0  # 0表示包含所有片段（对于vod类型）
    hls_flags = 'delete_segments'  # 不需要append_list，因为vod是完整的
    logger.info(f"检测到本地文件，使用VOD播放列表类型")
else:
    # 实时流：使用 event 类型，只保留最近的片段
    playlist_type = 'event'
    hls_list_size = 10  # 保留10个片段
    hls_flags = 'delete_segments+append_list'  # 追加模式
    logger.info(f"检测到实时流，使用EVENT播放列表类型")

cmd.extend([
    '-f', 'hls',
    '-hls_time', '2',
    '-hls_list_size', str(hls_list_size),
    '-hls_flags', hls_flags,
    '-hls_playlist_type', playlist_type,  # 关键：vod 或 event
    # ...
])
```

#### 优化效果
- **播放稳定性**：VOD类型不再频繁更新，播放流畅
- **避免重启**：播放列表完整，不会导致播放中断
- **自动识别**：根据视频源自动选择正确的类型

### 3. 前端HLS播放器优化

#### 3.1 VOD类型配置优化

**问题**：VOD类型使用了低延迟模式，缓冲不足，导致播放不稳定

**解决方案**：针对VOD类型优化播放器配置

**位置**：`src/lib/hlsPlayer.ts`

```typescript
this.hls = new Hls({
  enableWorker: true,
  lowLatencyMode: false,  // 对于vod类型，不需要低延迟模式
  maxBufferLength: 30,    // 增加缓冲长度（秒），适合vod类型
  maxMaxBufferLength: 60,
  maxBufferSize: 60 * 1000 * 1000,  // 增加缓冲大小（60MB）
  maxLoadingDelay: 4,
  minAutoBitrate: 0,
  startLevel: -1,  // 自动选择质量
  debug: false,
  // 对于vod类型，不要频繁重新加载清单
  manifestLoadingTimeOut: 10000,  // 清单加载超时（10秒）
  manifestLoadingMaxRetry: 1,     // 清单加载最大重试次数
  levelLoadingTimeOut: 10000,      // 级别加载超时
  fragLoadingTimeOut: 20000,       // 片段加载超时
  // ...
});
```

#### 3.2 URL路径修复

**问题**：hls.js错误解析相对路径，导致片段URL错误
- **错误URL**：`/api/streams/{id}/hls/playlist.m3u8/segment000.ts`
- **正确URL**：`/api/streams/{id}/hls/segment000.ts`

**解决方案**：使用`xhrSetup`拦截并修复URL

```typescript
xhrSetup: (xhr, url) => {
  // 修复错误的URL路径
  if (url.includes('/playlist.m3u8/')) {
    const fixedUrl = url.replace('/playlist.m3u8/', '/');
    console.log('HLSPlayer: 修复URL路径:', url, '->', fixedUrl);
    xhr.open('GET', fixedUrl, true);
    return;
  }
  // 正常URL，使用默认处理
  xhr.open('GET', url, true);
},
```

#### 3.3 VOD类型自动检测

**实现**：通过`MANIFEST_LOADED`事件检测播放列表类型

```typescript
this.hls.on(Hls.Events.MANIFEST_LOADED, (event, data) => {
  if (isFirstLoad) {
    isFirstLoad = false;
    // 检查播放列表类型
    if (data.levels && data.levels[0] && data.levels[0].details) {
      const isLive = data.levels[0].details.live;
      this.isVodPlaylist = !isLive;
      console.log('HLSPlayer: 播放列表类型:', isLive ? '实时流(event)' : '点播(vod)');
    }
  }
});
```

#### 3.4 客户端循环播放

**问题**：本地视频播放结束后停止，无法自动循环

**解决方案**：监听`ended`事件，对VOD类型实现循环播放

```typescript
// 监听视频播放结束事件，实现循环播放（仅对本地文件/VOD类型）
this.videoElement.addEventListener('ended', () => {
  console.log('HLSPlayer: 视频播放结束，重新开始播放（循环）');
  // 对于VOD类型的本地文件，重新开始播放
  if (this.isVodPlaylist) {
    this.videoElement.currentTime = 0;
    this.videoElement.play().catch(err => {
      console.error('HLSPlayer: 循环播放失败', err);
    });
  }
});
```

## 四、经验总结

### 1. FFmpeg编码优化原则

#### 性能优先策略
- ✅ **优先使用`ultrafast` preset**：编码速度最快，CPU占用最低
- ✅ **CRF 26是平衡点**：在检测场景下质量足够，性能提升明显
- ✅ **15fps足够检测**：对于AI检测场景，15fps完全满足需求
- ✅ **禁用不需要的功能**：音频、场景检测等都会增加CPU负担

#### 参数选择建议
```python
# 推荐配置（平衡性能与质量）
fps = 15          # 5-30fps，检测场景15fps足够
crf = 26          # 18-28，26是平衡点
preset = 'ultrafast'  # ultrafast/veryfast/fast，优先ultrafast
threads = 0      # 0表示自动，可限制为CPU核心数
```

### 2. HLS播放列表类型选择

#### 关键原则
- **本地文件 → VOD**：完整播放列表，不频繁更新
- **实时流 → EVENT**：动态更新，只保留最近片段
- **错误选择会导致播放异常**：重启、卡顿、无法播放

#### 判断逻辑
```python
is_local_file = not input_source.startswith(('http://', 'https://', 'rtsp://', 'rtmp://'))
if is_local_file:
    playlist_type = 'vod'
    hls_list_size = 0
else:
    playlist_type = 'event'
    hls_list_size = 10
```

### 3. 前端播放器配置

#### VOD类型配置要点
- ✅ **禁用低延迟模式**：`lowLatencyMode: false`
- ✅ **增大缓冲区**：`maxBufferLength: 30-60秒`
- ✅ **增加超时时间**：避免频繁重试
- ✅ **修复URL路径**：使用`xhrSetup`拦截修复

#### 实时流配置要点
- ✅ **启用低延迟模式**：`lowLatencyMode: true`
- ✅ **较小缓冲区**：`maxBufferLength: 10-20秒`
- ✅ **快速重试**：较短的超时时间

### 4. 问题排查思路

#### 系统化排查流程
1. **CPU占用高** → 检查FFmpeg编码参数（fps、crf、preset）
2. **播放不稳定** → 检查HLS播放列表类型（vod vs event）
3. **片段加载失败** → 检查URL路径解析（xhrSetup）
4. **无法循环播放** → 检查`ended`事件监听和VOD类型检测
5. **逐步验证** → 每次优化后测试效果，记录性能数据

#### 调试技巧
- 查看FFmpeg日志：`-loglevel warning`或`info`
- 查看浏览器控制台：HLS播放器日志
- 监控CPU占用：`top`或`htop`命令
- 检查HLS文件：直接访问`playlist.m3u8`查看内容

## 七、技术细节补充

### FFmpeg参数说明

#### Preset选项（编码速度）
- `ultrafast`：最快，CPU占用最低，文件稍大
- `veryfast`：很快，CPU占用较低
- `fast`：较快，CPU占用中等
- `medium`：平衡，CPU占用较高
- `slow`：较慢，CPU占用高，文件最小

#### CRF值说明（质量因子）
- `18`：高质量，大文件，高CPU占用
- `23`：默认质量，平衡
- `26`：较低质量，小文件，低CPU占用（推荐）
- `28`：低质量，最小文件，最低CPU占用

#### GOP大小说明
- GOP = Group of Pictures（关键帧间隔）
- 设为2倍FPS：15fps时GOP=30，平衡延迟与效率
- 较小GOP：延迟低但文件大
- 较大GOP：文件小但延迟高

### HLS播放列表类型说明

#### VOD (Video On Demand)
- **特点**：完整的播放列表，包含所有片段
- **适用**：本地文件、点播视频
- **更新**：不频繁更新，播放列表固定
- **配置**：`hls_list_size=0`（包含所有片段）

#### EVENT (Live Event)
- **特点**：动态播放列表，只保留最近片段
- **适用**：实时流、直播
- **更新**：频繁更新，追加新片段
- **配置**：`hls_list_size=10`（保留10个片段）
