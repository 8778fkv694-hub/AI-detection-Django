# 多页面工序隔离与工装码补录联调清单 v1

## 1. 目标

验证当前系统满足以下原则：

- 同功能不同页面可绑定不同工序，互不干扰
- 不同页面可绑定不同 YOLO 模型和 OCR 引擎
- 原有拼接图、批量检验、OCR/条码规则主流程不变
- 工装二维码作为独立追踪输入链存在
- 工装二维码优先走整图视觉识别
- 视觉失败时可切换扫码、NFC 或人工补录
- 最终统一落到同一个 `fixture_qr` 字段

## 2. 前置准备

### 2.1 数据库迁移

先执行迁移：

```bash
backend/venv/bin/python backend/manage.py migrate
```

### 2.2 启动系统

前端、后端按项目现有方式启动。

### 2.3 测试页面示例

工序1页面：

```text
/ocr?stage_code=step_1&stage_name=工序1&page_instance_id=page_1&camera_id=cam_1&ocr_model=rapidocr&fixture_qr_prefixes=FIXTURE-,JT-&fixture_qr_pattern=^FIXTURE-[0-9]{4}$
```

工序2页面：

```text
/ocr?stage_code=step_2&stage_name=工序2&page_instance_id=page_2&camera_id=cam_2&ocr_model=paddleocr&fixture_qr_prefixes=FIXTURE-,JT-&fixture_qr_pattern=^FIXTURE-[0-9]{4}$
```

## 3. 页面隔离验证

### 3.1 OCR 页面配置隔离

步骤：

1. 同时打开工序1页面和工序2页面
2. 在工序1页面修改检测目标、OCR 引擎、YOLO 模型
3. 切到工序2页面，确认其配置未被覆盖

预期：

- 两个页面的“页面绑定信息”面板显示不同的工序、页面实例、相机
- 工序1改动不会覆盖工序2的 OCR 页面配置

### 3.2 YOLO 模型隔离

步骤：

1. 工序1页面选择模型 A
2. 工序2页面选择模型 B
3. 分别触发实时检测或手动检测

预期：

- 工序1页面按模型 A 运行
- 工序2页面按模型 B 运行
- 两边互不覆盖

### 3.3 OCR 引擎隔离

步骤：

1. 工序1页面带 `ocr_model=rapidocr`
2. 工序2页面带 `ocr_model=paddleocr`
3. 分别执行 OCR 识别

预期：

- 工序1页面绑定信息显示 `rapidocr`
- 工序2页面绑定信息显示 `paddleocr`
- 结果保存后 OCR 引擎表现与页面绑定一致

## 4. 工装二维码主流程验证

### 4.1 整图中只有一个工装二维码

步骤：

1. 准备一张整图，图中只有一个符合规则的工装二维码
2. 在视觉模式下执行识别并保存结果

预期：

- 自动筛出工装二维码
- `fixture_qr` 成功写入
- 结果页显示工装二维码
- `traceConclusion` 不会因为工装码缺失而进入待补录

### 4.2 整图中有多个二维码，但只有一个符合工装规则

步骤：

1. 准备一张整图，包含多个二维码
2. 其中仅一个符合 `fixture_qr_prefixes` 或 `fixture_qr_pattern`
3. 执行识别并保存结果

预期：

- 自动筛出唯一工装二维码
- 结果页 `二维码候选数` 大于 1
- 最终写入的 `fixture_qr` 为符合规则的那个二维码

### 4.3 整图中有多个二维码，且无法唯一筛出工装二维码

步骤：

1. 准备一张整图，包含多个二维码
2. 多个二维码都满足当前工装规则，或都不满足
3. 执行识别并保存结果

预期：

- 不会盲选任意一个二维码作为工装码
- 结果页显示：
  - `traceConclusion = 存疑`
  - `fixtureQrFallbackRecommended = true`
  - 工装规则说明提示改用扫码、NFC 或人工补录

## 5. 工装二维码补录验证

### 5.1 视觉失败后扫码补录

步骤：

1. 在视觉模式下让工装码识别失败
2. 在 OCR 页面“工装二维码补录”区切换到 `扫码`
3. 输入正确工装二维码
4. 再次执行并保存结果

预期：

- 页面绑定信息中的工装输入方式变为 `scanner`
- 保存结果后 `fixture_qr` 使用补录值
- 追踪状态不再停留在“待补录工装码”

### 5.2 视觉失败后 NFC 补录

步骤：

1. 在视觉模式下让工装码识别失败
2. 在补录区切换到 `NFC`
3. 输入正确工装二维码
4. 执行并保存结果

预期：

- 页面绑定信息中的工装输入方式变为 `nfc`
- 保存结果后 `fixture_qr` 使用补录值

### 5.3 恢复视觉自动识别

步骤：

1. 页面已存在扫码或 NFC 补录值
2. 点击“恢复视觉自动识别”

预期：

- 补录值清空
- 输入来源恢复为 `vision`
- 后续继续按整图自动筛工装码

## 6. 业务码与工装码分离验证

### 6.1 工装码不应被当成业务码

步骤：

1. 准备整图，图中包含工装二维码和业务二维码
2. 确保工装二维码被成功筛出
3. 保存结果

预期：

- `fixture_qr` 使用工装二维码
- `business_code` 不应与 `fixture_qr` 相同
- 业务码应来自剩余候选二维码或 OCR 文本

## 7. 跨工序追踪验证

### 7.1 同工装跨工序归并

步骤：

1. 工序1页面保存一条结果，带相同 `fixture_qr`
2. 工序2页面再保存一条结果，带相同 `fixture_qr`
3. 打开 OCR 结果页查看详情

预期：

- 结果页“关联工序”中能看到工序1、工序2
- 能看到各工序的页面实例、相机、业务码

### 7.2 工序业务码匹配

步骤：

1. 工序1和工序2使用相同或可匹配的业务码
2. 保存结果

预期：

- 追踪结论可进入 `合格`
- 规则摘要提示存在通过的跨工序业务码比对

### 7.3 工序业务码冲突

步骤：

1. 工序1和工序2使用明显不匹配的业务码
2. 保存结果

预期：

- 追踪结论为 `需复检`
- 规则明细中出现跨工序业务码不匹配

## 8. 当前已知限制

- 二维码服务目前仍是共享单例，不是页面级不同二维码模型架构
- 部分旧接口仍保留全局切换模型语义，但 OCR 主链路和当前 YOLO 主链路已改为更稳定的请求级或默认模型策略
- 当前补录区先以页面输入形式实现，还没有对接真实扫码枪或 NFC 设备接口

## 9. 联调通过标准

满足以下条件即可认为第一阶段通过：

- 多页面配置互不覆盖
- 不同页面模型调用互不串扰
- 原有拼接图和批量检验链路未受影响
- 工装码可从整图中自动筛出
- 自动筛不出时可补录
- 同工装跨工序结果可归并
- 结果页可清晰看到追踪信息、候选数量和补录建议
