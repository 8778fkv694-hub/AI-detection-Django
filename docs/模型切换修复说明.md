# 模型切换持久化修复说明

## 问题描述

之前系统存在一个bug：后端模型被硬编码到滤芯检测模型，无法正常切换。即使前端切换成功，后端也会自动变回滤芯检测模型。

## 问题原因

1. **模型配置只存在于内存中**：`PPEModelConfig` 类中的模型配置没有持久化机制
2. **每次重启都重置**：Django服务重启时，模型配置会重新初始化，回到默认值
3. **缺少数据库集成**：虽然有数据库模型，但实际的模型切换逻辑没有与数据库集成

## 修复方案

### 1. 新增数据库模型

在 `backend/inspection/models.py` 中新增了 `ModelConfig` 模型：

```python
class ModelConfig(models.Model):
    """模型配置管理"""
    MODEL_TYPES = [
        ('PPE_YOLO', 'PPE YOLO检测模型'),
        ('YOLO_GENERAL', '通用YOLO模型'),
        ('FILTER_CORE', '滤芯检测模型'),
        ('CUSTOM', '自定义模型'),
    ]
    
    id = models.UUIDField(primary_key=True, default=uuid.uuid4, editable=False)
    model_type = models.CharField(max_length=20, choices=MODEL_TYPES, unique=True)
    current_model_id = models.CharField(max_length=100, help_text="当前激活的模型ID")
    model_config = models.JSONField(default=dict, help_text="模型配置信息")
    
    # 时间戳
    created_at = models.DateTimeField(auto_now_add=True)
    updated_at = models.DateTimeField(auto_now=True)
```

### 2. 更新模型配置类

修改 `backend/inspection/model_config.py`：

- `get_default_model()` 方法现在优先从数据库读取配置
- `set_default_model()` 方法现在会将配置保存到数据库
- 保持向后兼容性，如果数据库中没有配置则使用文件中的默认配置

### 3. 更新模型切换逻辑

修改 `backend/inspection/yolo.py` 和 `backend/inspection/views.py`：

- 模型切换时会同时更新内存配置和数据库配置
- 确保重启后能正确加载之前选择的模型

## 修复效果

✅ **模型切换持久化**：切换后的模型配置会保存到数据库，重启后不会丢失

✅ **向后兼容**：如果数据库中没有配置，会使用文件中的默认配置

✅ **API一致性**：前端API调用和数据库配置保持同步

✅ **错误处理**：如果数据库操作失败，会回退到内存配置

## 技术细节

### 数据库表结构

```sql
CREATE TABLE inspection_modelconfig (
    id UUID PRIMARY KEY,
    model_type VARCHAR(20) UNIQUE NOT NULL,
    current_model_id VARCHAR(100) NOT NULL,
    model_config JSONB DEFAULT '{}',
    created_at TIMESTAMP DEFAULT NOW(),
    updated_at TIMESTAMP DEFAULT NOW()
);
```

### 配置优先级

1. **数据库配置**（最高优先级）
2. **内存配置**（中等优先级）
3. **文件默认配置**（最低优先级）

### 错误处理

- 如果数据库连接失败，会使用内存配置
- 如果模型文件不存在，会跳过该模型
- 如果配置格式错误，会使用默认配置

## 注意事项

1. **首次部署**：需要运行数据库迁移命令
2. **模型文件**：确保模型文件存在于正确路径
3. **权限设置**：确保Django有数据库写入权限
4. **备份建议**：建议在部署前备份数据库

## 验证方法

1. 切换模型后检查数据库中的 `inspection_modelconfig` 表
2. 重启Django服务，验证模型配置是否保持
3. 使用前端界面切换模型，验证是否正常工作
4. 运行测试脚本进行自动化验证

修复完成后，模型切换功能将正常工作，不再出现自动变回滤芯检测模型的问题。
