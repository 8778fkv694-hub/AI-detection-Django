# Frame端点404错误排查指南

## 问题描述
`/api/streams/{id}/frame/` 端点返回404错误，但 `/api/streams/{id}/status/` 端点正常工作。

## 已完成的修复

### 1. URL拼接修复
- ✅ 修复了 `apiFetch` 函数，确保endpoint以 `/` 开头
- ✅ URL正确格式：`/api/streams/{id}/frame/?...`

### 2. Frame方法简化
- ✅ 简化了 `frame` 方法，使其与 `status` 方法一致
- ✅ 移除了多余的try-except包装

## 当前状态

### 测试结果
- ✅ `/api/streams/{id}/` - 200 OK（流媒体对象存在）
- ✅ `/api/streams/{id}/status/` - 200 OK（status端点正常）
- ❌ `/api/streams/{id}/frame/` - 404 Not Found（frame端点失败）

### 代码对比

**Status方法（正常工作）：**
```python
@action(detail=True, methods=['get'])
def status(self, request, pk=None):
    """获取流媒体状态"""
    stream = self.get_object()
    # ... 处理逻辑 ...
```

**Frame方法（已修复，与status一致）：**
```python
@action(detail=True, methods=['get'])
def frame(self, request, pk=None):
    """获取流媒体当前帧（Base64编码）"""
    stream = self.get_object()
    # ... 处理逻辑 ...
```

## 可能的原因

### 1. Django服务未重新加载代码 ⚠️ **最可能**
- Django开发服务器可能没有自动重新加载新代码
- **解决方案：** 手动重启Django服务

### 2. URL路由配置问题
- 检查 `backend/config/urls.py` 中的路由配置
- 确认 `router.register(r'streams', StreamSourceViewSet, basename='stream')` 存在

### 3. 代码缓存问题
- Python可能缓存了旧版本的代码
- **解决方案：** 清除Python缓存文件（`__pycache__`）

## 解决步骤

### 步骤1：重启Django服务（必须）

**停止Django服务：**
```bash
# 如果使用Ctrl+C，直接停止
# 或者查找进程并杀死
ps aux | grep "manage.py runserver" | grep -v grep | awk '{print $2}' | xargs kill
```

**重新启动Django服务：**
```bash
cd backend
python3 manage.py runserver 0.0.0.0:8000
```

### 步骤2：清除Python缓存

```bash
find backend -type d -name __pycache__ -exec rm -r {} + 2>/dev/null
find backend -name "*.pyc" -delete
```

### 步骤3：验证修复

```bash
# 测试frame端点
curl "http://localhost:8000/api/streams/cd2b481b-6f0a-4b6e-9250-215e4924c4d8/frame/?format=webp&quality=100&width=1280"
```

**预期结果：** 应该返回200 OK和WebP格式的帧数据

### 步骤4：检查Django日志

查看Django控制台输出，应该看到：
```
获取帧请求: stream_id=cd2b481b-6f0a-4b6e-9250-215e4924c4d8, format=webp
Node.js服务可用: True/False
使用 Node.js 服务获取帧: ... 或 回退到 Django
```
