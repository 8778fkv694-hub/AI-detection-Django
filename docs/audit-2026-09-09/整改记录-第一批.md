# 第一批整改记录：防漏单、串件和旧结果回写

整改日期：2026-09-09。对应审计报告 `docs/audit-2026-09-09/审计报告.md` 第 7 节"第一批"（A03/A04/A05/A06/A07/A11）。

## 整改内容

### A03 · 复位不能作废在途 OCR/LLM；旧结果和计时器仍可写回 → 已修复

- `src/hooks/ocr/useBatchResultHandler.ts`：每轮检测以唯一 `runId` 标识；`activeRunIdRef` 保存当前有效轮次，在 LLM await 之后、UI 写入前、保存前、保存回调后逐点校验；轮次被复位/取代时丢弃迟到结果（含融合 AI 本地状态复位 `resetFusionState`）。
- 自动放行的 2 秒延时器登记在 `autoNextTimerRef`，回调内先校验运行身份；`resetBatchSaveState` 升级为"作废在途轮次 + 清去重键 + 清计时器"。
- `src/hooks/ocr/useBatchProcessingManager.ts`：每次触发分配 `runId` 并传给结果回调。
- `src/screens/OCRDetectionScreen.tsx`：`inspectionRoundRef` 轮次身份；强制复位、确认继续均递增轮次，确认后的 1 秒清理延时器校验轮次，旧计时器不再把新流程设回 idle。

### A04 · 用识别内容去重，连续同款产品会漏记录 → 已修复

- 保存去重键由 `OCR文本_标签列表` 改为 `run:<runId>`（每次触发唯一）。同一轮内重复保存幂等（一次保存），不同件（新 runId）必然各存一条。验收：两件相同文字/标签产生 2 条保存。

### A05 · 保存失败不阻止进入下一轮 → 已修复

- `useDetectionSave.saveDetectionResult` 返回 `{saved, savedData, reason}`；保存失败（throw 或 `saved:false`）时批处理不自动放行：保持 `waiting_for_approval` + 等待确认，提示保存失败。
- 非融合模式下 OCR 失败（`success=false`）现在也保存"需复检"失败记录，不再"调用方视为保存完成却无记录"；无可保存结果时返回 `saved:false`。

### A06 · 视觉工装码跨件保留 → 已修复

- 后端 `product_trace_service._resolve_fixture_qr_from_candidates`：视觉来源绑定必须与当前图像候选交叉校验；当前图像存在唯一规则命中时以命中为准（新板换旧码 → 采用新码）；规则存在但旧码不符合规则时绑定判为可疑（`failed` → 存疑）；手工/扫码/NFC 显式绑定不受影响。
- 前端：自动继续、确认继续、强制复位时清除视觉识别的工装输入与上一件的追踪预览（`clearFixtureVisionBinding` / `prepareNextPiece`）。

### A07 · FQC 没有工装复用轮次 → 已修复（会话边界 + 兼容）

- 新模型 `FixtureLoadSession`（工装装载会话）；`InspectionResult.fixture_session` 外键；保存时由后端 `resolve_fixture_session` 解析/轮换会话。
- 会话轮换时机：前端声明 `fixtureNewRound`（产品循环进入下一件、强制复位；由 `traceContext.fixtureSessionId` 绑定纪元与 `fixtureNewRoundPending` 表达）且打开会话为空或已记录过同一工序（板子重新进入已完成工序 = 新件）时轮换；否则视为同一件的工序推进，沿用当前会话，避免把同件上游记录隔离出去。
- FQC `_collect_fixture_inspections`：触发记录携带会话时严格只收集同一会话记录；未携带会话（旧客户端/历史数据）保持旧行为（向后兼容）。FQC 生成后关闭会话。
- 已知边界（记录在案）：跳过首工序且上一轮未终检的快速复用，仍无法在无产品实例身份的情况下与"同件推进"区分（等价于审计 A07 修复方向中的 productInstanceId 装载生命周期，属第二批 A09 的产品实例持久化工作）；工装业务码比对（product_trace_service 跨工序业务码）仍可作为第二道防线。

### A11 · 后端结论未统一控制前端继续条件 → 已修复

- 保存回调读取后端权威结论（`trace_conclusion` / `fqc_overall_result` / `overall_quality`）：后端复核非合格时覆盖前端合格初判（`finalResult=unqualified`、报警灯已由 handleSaveComplete 按后端结论输出），并阻止自动放行（转人工确认）。前端初判在保存前显示，保存失败或后端拒绝不得当作最终合格。
