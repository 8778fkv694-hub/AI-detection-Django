# Frame端点绕过方案说明

## 问题
ViewSet的`frame` action端点返回404，即使路由已正确注册。

## 解决方案
创建了一个独立的函数视图，绕过ViewSet的action机制。

## 实现

### 1. 创建独立函数视图
在 `backend/inspection/stream_api.py` 中添加了 `get_stream_frame_direct` 函数：

```python
@csrf_exempt
@api_view(['GET'])
def get_stream_frame_direct(request, stream_id):
    """直接获取流媒体帧（绕过ViewSet的action机制）"""
    # ... 实现逻辑 ...
```

### 2. 注册URL路由
在 `backend/config/urls.py` 中，**在router之前**注册直接路径：

```python
urlpatterns = [
    path('admin/', admin.site.urls),
    
    # 直接获取帧的端点（必须在router之前，避免被router拦截）
    path('api/streams/frame/<uuid:stream_id>/', get_stream_frame_direct, name='stream_frame_direct'),
    
    path('api/', include(router.urls)),
    # ...
]
```

**重要：** 直接路径必须在router之前，否则会被router的URL模式拦截。

### 3. 更新前端API调用
在 `src/api/streamApi.ts` 中，`getStreamFrame` 函数优先尝试直接端点：

```typescript
export const getStreamFrame = async (...) => {
  // 优先尝试直接端点（绕过ViewSet action）
  try {
    return await apiRequest(`/streams/frame/${id}/?${params.toString()}`);
  } catch (error) {
    // 如果直接端点失败，回退到ViewSet action端点
    if (error.message?.includes('404')) {
      return await apiRequest(`/streams/${id}/frame/?${params.toString()}`);
    }
    throw error;
  }
};
```

## URL路径

### 新端点（推荐）
- **URL:** `/api/streams/frame/<stream_id>/`
- **方法:** GET
- **参数:** `quality`, `width`, `format` (查询参数)

### 旧端点（备用）
- **URL:** `/api/streams/<stream_id>/frame/`
- **方法:** GET
- **状态:** 如果新端点失败，会自动回退

## 优势

1. **绕过ViewSet问题：** 不依赖ViewSet的action机制
2. **简单直接：** 函数视图更简单，易于调试
3. **向后兼容：** 前端会自动回退到旧端点
4. **URL优先级：** 直接路径在router之前，确保匹配

## 测试

重启Django服务后，测试新端点：

```bash
curl "http://localhost:8000/api/streams/frame/cd2b481b-6f0a-4b6e-9250-215e4924c4d8/?format=webp&quality=100&width=1280"
```

应该返回200 OK和WebP格式的帧数据。

## 注意事项

1. **必须重启Django服务** 以加载新的URL路由
2. **URL路径顺序很重要** - 直接路径必须在router之前
3. **前端会自动处理回退** - 如果新端点失败，会自动尝试旧端点
